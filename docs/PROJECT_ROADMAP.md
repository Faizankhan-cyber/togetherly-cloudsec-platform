## Version gates

### V1 — Security Foundation
**Learning support:** DataCamp Python Fundamentals, DataCamp Intermediate Python, Bash and PowerShell foundations.

Build the local Python assessment tool, map application architecture, perform STRIDE threat modelling, assess relevant OWASP risks, review Zero Trust principles, validate findings, and document remediation.

### V2 — Identity & Cloud Security
**Learning support:** AZ-900, AZ-104, SC-500 and GH-900.

Design and test Microsoft Entra ID integration, OAuth/OIDC, application role mapping, Azure RBAC, Managed Identities and Key Vault. Preserve application-level authorisation and database RLS. Validate the architecture before any identity migration.

### V3 — Infrastructure & DevSecOps
**Learning support:** Terraform Associate (004), AZ-104, GH-900, AWS CLF-C02 and AWS SAA-C03.

Build reusable Terraform and Bicep infrastructure, Azure networking, GitHub Actions validation and controlled deployments. Use AWS learning for architecture comparison, not an unnecessary second production deployment.

### V4 — Security Operations
**Learning support:** SC-500, AZ-104 and AWS Certified Security – Specialty (advanced support).

Build log collection, KQL investigations, Sentinel detections, alerting and incident response exercises. Review service costs before enabling paid ingestion or security plans.

### V5 — Enterprise Architecture
**Learning support:** AZ-305 and AWS Certified Security – Specialty, supported by SAA-C03.

Complete governance, Azure Policy, backup and restore testing, disaster recovery planning, Zero Trust assessment, and final enterprise architecture documentation.

## Timing and status

- The user's target is to complete AZ-900, GH-900, AZ-104 and SC-500 by February 2027.
- The fourth BCA semester is planned for JavaScript, AWS foundations/associate study, and Terraform certification.
- Advanced architecture and cloud security certifications are planned for final year.
- These are targets, not completed credentials. Update this document when exam bookings, results, or semester timing change.

## Completion rule

A version is complete only when its implementation, tests, evidence, documentation and review criteria are satisfied. Passing a related certification alone does not mark a version complete.
